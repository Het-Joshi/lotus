lotus · a local agent for Ollama that fits small models

Files, shell, web and a real browser, driven by a 4–8B model on your own machine. Pure Python standard library, nothing to configure.

Install

curl -fsSL https://raw.githubusercontent.com/Het-Joshi/lotus/main/install.sh | sh

Install with browser control (adds Playwright and Chromium, about 150 MB)

curl -fsSL https://raw.githubusercontent.com/Het-Joshi/lotus/main/install.sh | sh -s -- --browser

Linux and macOS. Uses uv or pipx if you have them, otherwise a private virtualenv; never needs root. Elsewhere: pip install "lotus-agent @ https://github.com/Het-Joshi/lotus/archive/main.tar.gz". You'll need Ollama and a model, e.g. ollama pull qwen3:4b.

    Why it exists

    Most agent harnesses are built for frontier models and then pointed at Ollama. On a small local model they break quietly:

    • Silent truncation. Ollama drops whatever doesn't fit its default context, without an error. lotus reads each model's real limit, sizes num_ctx for every prompt, and warns before anything is cut.
    • Broken tool calls. Small models often write tool calls as text, or with the wrong argument names. lotus uses native calls when it can and rescues and repairs the rest.
    • Context rot. One log file fills the window and the model forgets the task. lotus pages long output, retires stale reads, keeps the plan at the end of the window, and compacts history into a structured summary.

    The system prompt is about 250 tokens. Tools come in packs that load only when needed.

    What's in it

    Tools
    Files, shell, grep, web search and fetch (optionally over Tor), clipboard, apps, notifications, charts and tables in the terminal, sub-agents with a fresh context.
    Browser
    Pages become text plus numbered elements, so a small model can say browser_click("3"). Asks before buy, send or delete buttons; site allow and block lists; tabs, dialogs and downloads handled.
    Control
    Esc stops a turn anywhere: the reply, a running command, the browser, sub-agents. Type while it works and your message is queued. Commands, writes and form input ask first.
    Memory
    LOTUS.md keeps instructions and facts for each project. .LOTUS_REM.txt notes where the last session left off, so the next one picks up there.
    Extending
    MCP servers, Python plugins (a function and a docstring is a tool), and recipes: saved prompts you can run on a schedule.
    Requirements
    Python 3.9+ and Ollama. No other dependencies; Playwright only for the browser.

    Use

    lotusinteractive session
    lotus "what's using port 8080?"one question, then exit
    git diff | lotus "commit message"pipe anything in; output is clean markdown
    lotus -rresume the last session
    lotus run standuprun a saved recipe
    lotus doctorcheck Ollama, models, browser, Tor

    Inside a session, type / for every command, @path to attach a file, !cmd to run a shell command yourself. The docs cover the rest.
